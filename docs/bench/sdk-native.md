# SDK-native decider benchmark

The Minecraft benchmark harness, rewritten on the decision-model support that
ships in the released Strands TypeScript SDK. It runs the same five tasks, the
same macro-action alphabet and the same world-verified verdicts as the v3
harness, and writes episode rows with v3's field names so the two can be read
side by side. It is a new harness: its results are labelled `sdk-native-v1` and
live under `bench-results/sdk-native/`. The v3 results
(`bench-results/RESULTS-v3.md` and the dated v3 directories on `feat/bench-v3`)
are not touched, re-scored or regenerated by anything here.

Code: `src/bench/`. Tests: `test/bench-*.test.ts`.

## What the SDKs ship (verified 2026-11-09)

| | TypeScript | Python |
|---|---|---|
| Package | `@strands-agents/sdk` | `strands-agents` |
| Latest release | 1.24.0 (npm, 2026-11-04) | 1.64.0 (PyPI, 2026-11-04) |
| `DecisionModel` + `LLMDecisionModel` | since 1.21.0 (2026-10-14) | since 1.63.0 (2026-10-30) |
| System One providers (`TypeSafeDecisionModel`, `DecisionsAPIDecisionModel`) | since 1.23.0 (2026-10-30) | 1.64.0 (2026-11-04) |
| Import | `import { DecisionModel, TypeSafeDecisionModel, LLMDecisionModel, Uncertain } from '@strands-agents/sdk'` | `from strands.decisions import DecisionModel, LLMDecisionModel` |

Both SDKs are built from one monorepo,
[strands-agents/harness-sdk](https://github.com/strands-agents/harness-sdk)
(`strands-ts/src/decisions/`, `strands-py/src/strands/decisions/`); tags
`typescript/v1.24.0` and `python/v1.64.0` are commit `0bd132a06`. The design
note the source cites is `team/designs/0020-decision-models.md`. Relevant
commits: `8340c4241` (TS primitive), `aa2da86ee` (TS System One providers),
`0cb69d419` (TS: HTTP 503 → `ModelThrottledError`).

The API (TypeScript, 1.24.0):

```ts
abstract class DecisionModel {
  ask<const Q extends Record<string, Question>>(state: DecisionInput, questions: Q, options?: AskOptions): Promise<DecisionResult<Q>>
  protected abstract _ask(state, questions, options): Promise<DecisionResult<Q>>
}
interface Question { question: string; choices: 'boolean' | readonly string[]; uncertainty?: boolean | { minConfidence?: number } }
// DecisionResult: { answers, usage?, metadata: { latencyMs, providerName?, modelId?, probabilities?, confidence? } }
```

`ask()` validates the questions, opens a `decision` OpenTelemetry span and
records usage; subclasses implement `_ask`. The System One providers send
`POST {state, model, questions}` with `noul` for boolean questions and `choice`
with `criteria: {id: null}` for choice questions, to a fixed endpoint
(`https://api.typesafe.ai/v1/systemone`, `https://decisionapi.net/v1/systemone`).

The decision model itself is [strands-labs/strands-decider](https://github.com/strands-labs/strands-decider)
(earlier name: Hobson). PyPI `strands-decider` 0.3.0 (2026-11-05, tag `v0.3.0`
= `87d0fd577`). `strands-decider serve <checkpoint>` exposes the same
`/v1/systemone` wire. Checkpoint used here:
`StrandsAgents/strands-decider-2B-qwen3.5-v1-2610` (4,096-token window).

## Why there is one subclass

The harness uses the SDK's `DecisionModel` for every policy arm. The hosted
providers are used as shipped (`TypeSafeDecisionModel` for Jev,
`LLMDecisionModel` for the LLM-on-the-alphabet control). A self-hosted
strands-decider needs `SelfHostedDecisionModel` (`src/bench/decider.ts`), a
~100-line `DecisionModel` subclass, for three reasons found while building
this:

1. **No base URL.** Neither SDK's System One providers take an endpoint. The TS
   one takes a `fetch`, which can redirect the request, but see 2.
2. **The SDK parser rejects strands-decider's answers.** strands-decider 0.3.0
   rounds each probability to 4 decimal places. Over 12 options the sum lands
   at 0.9999, and the SDK requires `|sum − 1| ≤ 1e-6`. A live probe against the
   local server (12 options, `TypeSafeDecisionModel` with `fetch` redirected)
   failed 5 of 5 calls with `probabilities for question id=<next_action> must
   sum to 1`. The subclass accepts up to 1e-3 and stores the raw sum per
   decision (`prob_sum`); it does not renormalise. Pinned by
   `test/bench-decider.test.ts`. This is worth raising upstream.
3. **Choices carry no descriptions.** The native `Question.choices` is a list
   of ids. The macro-actions need their grounding text (`fell_tree_0 — Fell the
   oak_log tree (5 logs) at (12, 70, -3)…`), which v3 sent as `criteria` values
   and the decider renders option by option. The subclass accepts an optional
   `descriptions` map and puts it in `criteria`. For SDK-native providers the
   descriptions are folded into the question text instead. Which way was used
   is recorded per episode as `option_rendering` (`criteria` |
   `question_text`).

Everything above the wire (validation, the span, usage, `Uncertain`, error
classes) is the SDK's.

## Language choice: TypeScript

- **SDK maturity.** TypeScript shipped `DecisionModel` two releases earlier
  (1.21.0 vs Python 1.63.0) and has a `fetch` seam on its System One
  providers. Both have the same API shape and the same limitations above.
- **Upstream architecture.** cagataycali/strands-minecraft is TypeScript: the
  body, the 60 tools, the reflexes and sentinel are TS modules. v3 needed a
  Node sidecar plus an MCP hop from a Python brain because of that. In
  TypeScript the harness imports those modules directly. The branch is cut
  from upstream `main` (`d46e87b`) and adds `src/bench/` plus one shared module
  (`src/body-rails.ts`, the pain/hunger/death rails moved out of `index.ts`, as
  v3 did). No sidecar, no Python, no strands-py fork.
- **Test tooling.** Upstream's `node:test` + `tsx` suite and its `fake-bot`
  run the harness tests with no server; `npm test` and `npm run typecheck` gate
  them with everything else.

Python would have kept the v3 brain code but also the sidecar, the second
language and v3's pinned strands-py fork (`7599ed078`), which used
`strands.experimental.decisions` (`Choice`/`YesNo`). That module is not in the
released 1.64.0 wheel.

## What stays comparable with v3

| | v3 | sdk-native-v1 |
|---|---|---|
| Tasks, step caps, wall caps | logs16 20/420s · wood_tools 24/480s · cobble8 32/600s · iron1 48/900s · night ∞/660s | same (`src/bench/tasks.ts`) |
| World | itzg 1.21.11, seed 8675309, tmpfs, fresh per episode, easy/survival | same `docker run` (`src/bench/world.ts`, pinned by test) |
| Body | Node sidecar over MCP | same modules in-process; one episode per child process |
| Reflexes | item_magnet, elbow_room, idle_staring off; safety on | same |
| Alphabet + candidates | policy.py | ported 1:1 (`src/bench/policy.ts`) |
| Verdicts | verify.py, world-checked | ported 1:1 (`src/bench/verify.ts`) |
| Decision state | aligned history, no empties, per-model char budget measured as `json.dumps` | same; budget measured with `pyJson` (Python separators) |
| Questions per step | `next_action` + `last_step_succeeded` | same |
| Agent arm | LLM + tools, `limits={"turns": 4}` per step | SDK `Agent`, same tools, upstream system prompt, `limits: { turns: 4 }` |
| Telemetry | Episode JSONL | same field names, plus `strands_sdk`, `option_rendering`, `setup_s`, per-decision `prob_sum` |

One difference to name when comparing: v3 sent the state as a JSON object and
the decider rendered it with `json.dumps(indent=2, ensure_ascii=False)`; this
harness sends `JSON.stringify(state, null, 2)` text. Both produce the same
layout and key order; float formatting can differ (Python prints `20.0`, JS
`20`) where a value arrived as a float.

Every agent gets the same action and state budget: one decision per step, the
task's step and wall caps, and (policy arms) the profile's state budget. The
loop checks the wall cap before each step; the agent arm also cancels a turn at
the deadline. Success is `task.check()` over body state after each step.
Infrastructure failures (`error`) are counted apart from model failures, and an
episode process that dies without writing a row gets an infra row.

## Run it

Prerequisites: Node ≥ 22, Docker, `npm install` (if `canvas` lost its native
build to blocked install scripts, copy `node_modules/canvas/build` from an
identical-version checkout).

**1. Serve the decider** (local, CPU works; ~1–7 s per decision on 32 CPU cores):

```bash
uv venv -p 3.12 .venv-decider
VIRTUAL_ENV=$PWD/.venv-decider uv pip install --extra-index-url https://download.pytorch.org/whl/cpu strands-decider==0.3.0
.venv-decider/bin/strands-decider serve StrandsAgents/strands-decider-2B-qwen3.5-v1-2610 --device cpu --port 8099
curl -s localhost:8099/health
```

Use `--device cuda` on a GPU host. Point the harness elsewhere with
`STRANDS_DECIDER_URL`.

**2. Smoke episode:**

```bash
npm run bench -- run --arms decider --tasks wood_tools --n 1 --run-id smoke
npm run bench -- report bench-results/sdk-native/smoke
```

**3. A cohort:** `--arms decider,jev,llm-policy,agent --tasks logs16,wood_tools,cobble8,iron1,night --n 3`.
Arms within one (task, episode) are interleaved.

| arm | model | needs |
|---|---|---|
| `decider` | `SelfHostedDecisionModel` → strands-decider | a server at `STRANDS_DECIDER_URL` |
| `jev` | SDK `TypeSafeDecisionModel` | `TYPESAFE_API_KEY` |
| `llm-policy` | SDK `LLMDecisionModel` over the env's model, same alphabet | `STRANDS_MODEL_PROVIDER` / `STRANDS_MODEL_ID` + creds |
| `agent` | SDK `Agent` with the body's tools | same |

**Where results go:** `bench-results/sdk-native/<run-id>/episodes.jsonl`, plus
`run.json` (arms, tasks, n, argv). The CLI refuses any `--out` under
`bench-results/` outside `sdk-native/`, and refuses to append to an existing
run unless `--append yes`.

Knobs: `BENCH_MC_IMAGE`, `BENCH_MC_VERSION`, `BENCH_SEED`, `--port-base`
(default 25600; the world uses it and +1), and v3's `POLICY_*` variables
(`POLICY_STATE_CHARS_DECIDER` defaults to 7,500, v3's Hobson budget).

## Validation on this branch

Smoke run 2026-11-09, CPU decider on this host (no paid infra), wood_tools,
n = 1: success in 5 decisions (explore_north, fell_tree_0,
craft_crafting_table, place_crafting_table, craft_wooden_pickaxe, each `done`
by the world check), loop 48.4 s, decide 21.1 s, setup 34.1 s, 57 tool calls,
0 deaths. Two of the five answers had `prob_sum` 0.9999. One episode is a
smoke test, not a result.
